# How the pipeline compares

Each row of the table below is a stage of the decoding pipeline in this
repository, in the order a read goes through them, with the modules that
do it under its name (paths under `src/`). Each column is a reader: QR
Forensics is this repository, and the other nine are open-source
libraries, each in the release named in the first row and in its default
configuration. Every cell was read from the library's source rather than
its documentation; the sources are listed after the notes.

QReader and Arbez find symbols with a neural network and hand each one to
another library to decode: QReader to ZBar, Arbez to zxing-cpp (note 1).
In their columns, "As ZBar" and "As zxing-cpp" mean that library does
that stage. "Table 9" is the table in ISO/IEC 18004 that keeps some
error-correction codewords of the smallest symbols for detecting misreads
rather than correcting them (note 4).

## Notes

1. **QReader and Arbez.** QReader decodes each crop with ZBar, through
   pyzbar, and with nothing else; if its network finds no symbol, nothing
   is decoded. Arbez decodes each crop with zxing-cpp at its default
   options (`tryHarder`, `tryInvert` and `tryDownscale` on; `tryRotate`
   is on too, but zxing-cpp's QR Code reader never consults it). A plain
   `arbez.Scanner()` also runs zxing-cpp over the whole photo, Apple
   Vision on macOS and, when installed, OpenCV's wechat_qrcode built with
   no model files, so without either of its networks. It then merges
   what the engines find by the overlap of their boxes.

2. **The extra codeword of a longer block.** In 128 of the 160 versions
   and levels of QR Code, from 5-Q and 5-H up, the blocks are of two
   lengths, and each longer block has one more data codeword than the
   shorter ones. ISO/IEC 18004 places those extra codewords after the
   full rows of interleaved data codewords, one for each longer block in
   turn; ZXing, zxing-cpp, ZBar, OpenCV and this repository read them
   from there. quirc (`codestream_ecc` in `lib/decode.c`) and BoofCV
   (`copyFromRawData` in `QrCodeDecoderBits.java`) read data codeword
   *i* of block *b* from *i* × *blocks* + *b* for every *i*, the last
   one too. For a longer block that lands the number of shorter blocks
   further on, among the other extra codewords or the first
   error-correction codewords. Applied to
   `tests/fixtures/qrencode_qr_5q_mixed_blocks.txt`, a version 5-Q symbol
   made by libqrencode, the standard order leaves all four blocks with
   zero syndromes, and the order quirc and BoofCV use leaves both longer
   blocks with one wrong codeword each. Reed–Solomon corrects it, so a
   clean symbol still reads, but each longer block has one codeword less
   left to correct damage with.

3. **ZBar's ECI designators.** `qr_code_data_parse` in
   `zbar/qrcode/qrdec.c` takes the high bits of a two-byte designator as
   `bits & 0x3F << 8`, which C reads as `bits & (0x3F << 8)`: nought for
   an eight-bit value, so only the low byte survives, and 899 becomes
   131. The three-byte form has the same slip. The character set ECIs in
   common use are below 128 and are not affected.

4. **Table 9.** A version 1-L symbol has 7 error-correction codewords,
   but ISO/IEC 18004 reserves 3 of them for detecting misreads, so it
   may correct 2 wrong codewords rather than 3. Versions 1-M, 1-Q, 1-H,
   2-L and 3-L reserve 2, 1, 1, 2 and 1, and Micro QR reserves some at
   M1, M2 and the L level of M3 and M4 (`misdecode_protection` in
   `src/symbol/tables.rs`). Of the libraries, only ZBar applies it, to
   version 1 and 2-L. OpenCV spends every codeword on purpose: a
   comment in `QRCodeDecoderImpl::errorCorrectionBlock` names three test
   images that need the reserved codewords, two of them from BoofCV's
   benchmark. So does `tests/opencv/err_correct_2L.png`, a 2-L symbol
   with five wrong codewords, which OpenCV reads. This repository reads
   it too, marked beyond the standard. It reports when a solution spends
   the reserve, but judges it by its chance of being wrong like any
   other: the reserve is a fixed, worst-case margin against misreads,
   while that chance measures the risk for the actual solution. At the
   code's own limit, every reserved level except M1 still confirms by 14
   bits or more, and a 1-L block with three wrong codewords is as well
   confirmed as an M3-M block with four, which the standard allows.
